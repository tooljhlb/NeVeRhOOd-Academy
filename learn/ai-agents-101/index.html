AI Agents 101: Tools, Permissions & Evidence

A free, original self-study lesson introducing safe AI tool orchestration. Complete five practice questions and see why engineering evidence matters.

1. A model and an agent are not identical

A model predicts outputs from inputs. An agentic application adds a control loop, tools, memory, a task objective, and explicit authorization. A useful agent must also handle failures, retries, cancellation, resource limits and logging.

2. Tools need strict boundaries

Wizards/Wands-like registries can expose named tools and schemas to a model. The executing server—not the model's text—must decide whether a tool is allowed. Validate names, arguments, identities, permissions, timeouts and side effects.

3. Separate data from execution

JSON is convenient at external API boundaries. Protobuf is useful for versioned typed messages. FlatBuffers can provide efficient access to read-heavy binary records. None automatically makes a system more secure or faster: benchmark the actual workload.

4. Evidence and reproducibility

A green test proves only the contract it exercised. Maintain source revision, input hash, output hash, environment version, tested device, result, and failure receipts. A mock response is not proof that a real model loaded.

5. Human-approved deployment

For third-party accounts, money, publication or destructive actions, use explicit approval, narrow permissions, and durable audit records. An AI assistant should help learners understand concepts, not pretend to earn external credentials for them.
