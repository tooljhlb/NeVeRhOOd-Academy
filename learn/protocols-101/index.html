Protocols 101: JSON, Protobuf & FlatBuffers

Choose a format with measurements, not hype.

1. Design the message contract

A wire format does not replace the schema and compatibility rules. Define stable field identities, missing-field behavior, version negotiation and validation before optimizing serialization.

2. JSON is a useful boundary

JSON is inspectable and widely supported for public APIs. Its text encoding may add parsing cost and payload size, but its flexibility often matters more than raw throughput at a browser interface.

3. Protobuf controls

Protocol Buffers encode typed messages compactly. Field numbers are stable identifiers, new optional fields can be added compatibly, and reserved field numbers should not be reused.

4. FlatBuffers read paths

FlatBuffers allow direct random-access reads from serialized buffers, a strong fit for read-heavy data. Builder costs, verifier requirements, padding and schema discipline still matter.

5. Benchmark the real hot path

Measure p50/p95 end-to-end encode+decode latency, allocations, payload bytes and throughput on realistic sizes; test compatible readers and malicious payload rejection. Avoid claiming one universal winner.
