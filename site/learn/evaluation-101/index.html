Model Evaluation 101: Receipts, Leakage & Reliability

Learn how to measure AI rather than infer quality from a model card.

1. Evaluate the actual artifact

A checkpoint, tokenizer and runtime form a tested combination. Documentation about the intended architecture does not prove that the current checkpoint generates acceptable answers.

2. Protect the held-out set

Separate training, tuning and final evaluation at the source/author/document-family level. Duplicate or near-duplicate leakage can make a weak model appear stronger.

3. Record proof receipts

Capture exact artifact SHA-256, model revision, tokenizer revision, dataset lineage, prompt versions, hardware, run configuration, per-case outcomes and raw predictions.

4. Compare against controls

Use a baseline, a shuffled/control condition where meaningful, fixed evaluation cases, confidence intervals and regression thresholds. Report refusals, hallucinations and tool correctness, not only overall accuracy.

5. Promote with gates

An improved score is not sufficient if language retention, privacy boundaries, restore integrity or latency regress beyond tolerance. A refused candidate is a valid engineering outcome.
